## 4. 재현 및 무결성 대조 절차

```bash
# (a) 현재 파일이 동결 시점과 같은지 확인
shasum -a 256 data/vm_all_1250_loaded.csv data/fastStorage_loading_manifest.csv \
              src/load_data.py docs/GWA_T12_데이터_로딩_설계안.md

# (b) 원본에서 다시 생성 (출력은 동일 체크섬이어야 한다)
python3 src/load_data.py
```

`src/load_data.py`는 입력 값을 변환하지 않으므로, 동일 원본 + 동일 스크립트는 **동일 바이트 출력**을 낸다. 체크섬이 달라졌다면 원본이나 스크립트가 변경된 것이다.

## 5. 동결 시점에 관측된 사실 (해석·처리는 미정)

로딩 과정에서 전수 확인된 값들이다. **어떤 보정도 적용하지 않았다.**

1. **`CPU cores = 0`인 행이 존재한다.** 전체 고유값: `0, 1, 2, 4, 6, 8, 16, 32`.
2. **VM별 행 수 편차가 극심하다.** 최소 5행(vm 312) ~ 최대 23,692행(vm 842).

   | 행 수 구간 | VM 개수 |
   |---|---|
   | 10행 미만 | 3 |
   | 10 ~ 99 | 6 |
   | 100 ~ 999 | 7 |
   | 1,000 ~ 7,999 | 80 |
   | 8,000 이상 | 1,154 |

3. **`Timestamp [ms]`는 초 단위로 보인다.** 전체 범위 `1376314846 ~ 1378906798`.
   - 초로 해석: `2013-08-12 13:40:46 UTC ~ 2013-09-11 13:39:58 UTC` → **정확히 30일**, 공식 `fastStorage` 공개 기간과 일치.
   - 밀리초로 해석: 1970-01-16 → 성립하지 않음.
   - 따라서 **컬럼명의 `[ms]`는 실제 단위와 불일치**할 가능성이 매우 높다. 단, 동결 기준선은 **원본 숫자 그대로**이며 단위 확정과 개명은 정제 단계에서 결정한다.
4. **`6.7108864E7` 같은 지수 표기는 `67108864.0`으로 평문화**되었다. float64 왕복이므로 값·정밀도는 동일하다.

## 6. 동결 이후 변경 규칙

- `data/vm_all_1250_loaded.csv`는 **정제 단계의 입력으로만 읽는다.** 덮어쓰지 않는다.
